# 错误分类与有限兜底

此文描述当前实现，需由独立审查核实，不代表所有供应商错误已实测覆盖。

## 响应分类

| 情况 | 行为 |
|---|---|
| 401或明确无效/过期Key，包括智谱HTTP200、code401、success=false | 凭证失效，跳后续候选；余额查询成功不会自动解封生成权限，需手动验证/换Key |
| 明确余额不足、用户额度不足、订阅日/周/月耗尽 | 标记额度耗尽，跳后续；5分钟额度刷新确认恢复；无限Token仍需生成探测证实账号可用 |
| 429且不是明确余额/周期耗尽 | 限流等待，Retry-After数字秒限制1–3600，无有效值60秒 |
| 400/413/422且未命中明确凭证、额度或限流特征 | 直接返回，不跳下一家，不惩罚渠道 |
| 未知403/404、5xx、重定向、网络错误、未知业务错误 | 归服务/协议异常，暂停该Key路由，触发有限恢复探测 |
| HTTP200非SSE | 不设正文大小上限；验证完整Responses结构或识别业务错误，成功正文原字节返回 |
| HTTP200 SSE开头失败 | 尚未提交时切换；使用错误帧分类凭证/额度/服务 |
| SSE已经输出后明确失败 | 不重放；失败标记后续请求避开，保留原始事件字节 |

业务请求和响应不再配置大小、并发数量或聚合内存配额。空SSE在提交前返回502 `empty_upstream_response`，不重放。

SSE观察支持大data行的顶层type识别、LF/CRLF/CR及兼容终态别名。正常EOF但未识别终态时，原字节透传并正常关闭HTTP正文，只记一次协议观察警告，不把格式差异当作Key故障。此时并不保证业务答案完整，客户端仍须检查业务终态。真实传输错误/600秒空闲超时仍记录服务故障；已提交时保留已收字节并关闭正文，不拼接或伪造终止事件。

分类只读取错误信封字段，不扫描正常模型回答里的“余额不足”等文本。未知错误不能直接宣称“Key错误”或“没钱”。

## 请求级上限

- 候选按配置顺位遍历且去重，不设8候选上限，总切换预算600秒。
- 候选身份是实际Responses URL、上游模型、Key的组合；同一凭证被重复配置也不重复尝试。
- 发送前重读该Key状态，减少并发失败时继续撞坏渠道。
- 请求上传总时限600秒，完成上传后开始切换预算；上游连接、响应头、错误正文和非流式正文等待最多600秒，候选阶段同时受总截止约束。
- SSE响应头后观察窗口最多10秒：提前发现失败可切换；到时即提交现有流（包括尚无字节），继续等待，静默本身不判故障、不重放。提交之后的失败交由客户端处理。
- 不在同一请求里sleep等待坏渠道恢复；已输出后不切换。
- “总切换600秒”不是有效长SSE流的总时限；有效流采用600秒读取空闲超时。

## 恢复级上限

首次服务异常暂避该Key，约5秒后最小请求确认；确认成功解除暂避，确认失败或10分钟内恢复后再次独立业务故障进入正式故障流程。疑似阶段不发送服务中断告警。正式故障的后台最小请求按1/2/3/4/5分钟等待，此后每5分钟。每个故障周期最多12次自动恢复探测，包括尚未完成恢复门槛的成功探测；耗尽后设置probe_exhausted，页面“待手动验证”，停止自动探测。没有用户请求能绕过此状态。

手动“重新验证”会检查额度、服务连通性及绑定的质量监控；真实探测成功后立即清除故障、暂时异常、探测耗尽和历史冷却，恢复路由资格。页面只保留这一个按钮；旧客户端传入 reset 参数仍兼容。修改实际渠道/Key配置会重置对应状态。普通排序、显示名称变化和重启不会解除故障；按上游地址、上游模型、凭证、有效额度适配器的身份指纹保留状态。手动检查遇到已有任务或配置变更返回409，可能保留已完成的部分检查。

同一故障被并发请求发现，只计一次故障周期。自动恢复要求两次成功且相隔至少60秒。不再使用冷却或恢复回切观察阻塞路由；旧cooldown_until字段仅保留兼容。每个新请求按优先级选择，确认降智的关联渠道必须排除。

恢复探测遇到HTTP429按Retry-After延后（60–3600秒，缺省300秒），不计入故障探测预算。手动操作仍可重开预算。

余额每5分钟刷新是只读检查，不发送用户生成请求；普通限流按等待期重试后续新请求，不无限循环当前请求。5分钟是目标周期；4个后台网络许可与慢上游会延后实际检查，大配置下一轮需等待当前批次完成。

自动切换不能保证上游未执行或未计费：响应头错误、早期明确失败或传输错误后的切换仍可能重复执行。全部候选失败保留统一503 `no_available_channel`，详细原因在管理页；不向员工暴露供应商凭证/错误正文。

## 实测证据

- 兼容渠道假Key：HTTP401，顶层INVALID_API_KEY。
- New API兼容渠道假Key：HTTP401，嵌套error、code空串、Invalid token。
- DeepSeek假Key：HTTP401，authentication_error。
- 智谱假Key：HTTP200，code401，success=false。
- 订阅额度耗尽：HTTP429，USAGE_LIMIT_EXCEEDED，正文WEEKLY_LIMIT_EXCEEDED。
- Sub2API余额不足：HTTP403，INSUFFICIENT_BALANCE。
- New API用户额度不足：HTTP403，insufficient_user_quota。
- 上游无可用账号：HTTP503，NO_AVAILABLE_ACCOUNTS。

原始脱敏结果在本机忽略目录.runtime；独立Agent不可假定该目录一定存在。未真实触发的分支由隔离模拟验证，应明确与实测区分。
