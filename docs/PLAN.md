# Forest Router 实施计划

> 历史记录：描述初期计划/当轮审查修复，不是当前运行规范。后续已取消业务大小/并发/8候选限制、冷却和回切观察，超时改为600秒，并加入员工Key管理。当前规则以README、ERROR-HANDLING.md为准。

状态：实现与验收结果见 ACCEPTANCE.md；正式服务器部署由用户提供环境后执行。

## 已确认范围
- Rust 单实例内网 Responses 透传服务；只修改上游 URL、认证 Key、顶层 model。
- 不注入提示词，不转换协议，不修改推理历史；公司 API Key 与上游 Key 明文保存。
- 管理密码登录；本地 JSON 配置、状态持久化，无数据库。
- 模型 → 有序渠道 → 多 Key。渠道按优先级，组内轮询，独立 Key 状态。
- 添加渠道时实际探测平台与额度接口：New API、Sub2API；现有订阅站专用适配。
- 模型名包含 deepseek 或 glm（ASCII 大小写不敏感）分别使用 DeepSeek 官方余额、智谱官方 Coding Plan 额度适配，优先于中转平台识别。请求协议仍为 Responses，实际支持情况须验证。
- GLM 分别显示 5 小时、周剩余额度百分比和重置时间；缺失字段显示未知。
- 真实验证仅使用显式提供并授权的外部配置；不修改原配置、不中断现有服务、不输出 Key。
- 质量监控仅检测绑定 ID，未绑定不拦截。满血、降智、未知分开。
- 默认时间段可在管理页调整。上海时区：09–23 每5分钟；23–04、07–09 每20分钟；04–07 每60分钟。
- 额度每5分钟更新，明确耗尽立即拦截，查询异常不等于耗尽。
- 服务故障自动跳下一候选，仅响应提交前重试；已输出的流不拼接新回答。
- 恢复探测间隔1/2/3/4/5分钟，此后5分钟；短时间反复故障冷却，支持手动验证和重置冷却。
- 飞书正常→降智、可用→耗尽、正常→故障事件去重通知；重启保留通知状态。
- 管理导航：配置中心、降智监控、日志、设置；模型和渠道三栏布局。
- 当前首选渠道绿色边框，降智紫色、故障红色、额度/冷却橙色；跳过原因可直接看到，正常备用标注优先级较低。当前首选与最后实际使用分别表达。
- 日志只展示最近200条事件，不逐请求展示；包含切换、状态改变和配置事件，敏感值脱敏。

## 执行阶段
1. 核实本地检测逻辑、真实配置结构及官方/中转额度接口，形成脱敏探测报告。
2. 实现 Rust 配置、状态机、额度适配与有界事件记录。
3. 实现 Responses 流式代理、取消处理、候选重试和恢复调度。
4. 实现质量检测、通知去重与本地持久化。
5. 实现管理界面、登录、配置编辑、状态展示及手动操作。
6. 隔离模拟故障验收、真实渠道验证、UI验证、负载与内存检查、构建与部署文档。

## 内存与并发验收
- 请求体、响应探测体、SSE观察缓冲有显式上限；不缓冲完整正常响应。
- 并发请求、检测任务、通知队列、连接池、事件环形队列有界。
- 客户端取消释放上游与并发许可，不遗留后台转发任务。
- 历史检测仅保存有限摘要，不常驻完整答案和提示词。
- 配置变更清理删除渠道缓存；每个检查去重，旧查询不能覆盖新故障。
- 测量空闲、持续请求、取消与故障后的RSS趋势；不能仅凭Rust无GC宣称无泄漏。
