# 两份独立审查处理记录

> 历史记录：描述初期计划/当轮审查修复，不是当前运行规范。后续已取消业务大小/并发/8候选限制、冷却和回切观察，超时改为600秒，并加入员工Key管理。当前规则以README、ERROR-HANDLING.md为准。

日期：2026-09-23。A指首份报告的P编号，B指第二份报告的F编号。修复验证全部使用本地假上游、随机端口、独立临时数据目录；没有调用真实供应商、发送真实飞书消息或部署。报告中的既往实测记录不等于本轮重测。

## 路由与响应

| 对应项 | 处理与证据 |
|---|---|
| A P1-1，大终态/空HTTP响应 | 已修复。有界增量扫描顶层type，支持大data行、别名和CR分行；正常EOF不再因未知终态产生body Err或隔离Key。单测覆盖100KB前/后置type、嵌套type不冒充、逐字节分片；HTTP回归70KB data-only终态完整返回。未知终态记录警告，不能据此承诺答案完整。 |
| A P2-1 / B F2，响应本地超限 | 已修复。9MiB假上游返回明确502 response_too_large；只执行一个候选、Key无故障。内存预算不足也独立处理。 |
| A P2-2，400/422 | 已修复。明确凭证/额度/限流优先，其余400/413/422直接返回。Unsupported parameter和FastAPI 422均验证原状态、不重放、不隔离。 |
| A P2-3 / B F1，首帧10秒 | 已修复。10秒改为观察提交窗口，之后继续读当前流；11秒首帧回归200且只执行一次、Key正常。已文档化120秒流空闲上限。 |
| A P3-2 / B F3，成功信封 | 已修复。合法status/output信封容忍额外code及空error对象；明确success=false/非空error仍不能伪装成功。HTTP code:ok/error:{}回归通过。任意data包装仍不属于支持的Responses。 |
| A P3-3，TCP分片决定重放 | 已修复。按先前完整语义帧判断；delta+failed同分片与分开到达均透传一次、不重放，故障记账相同。EOF处理末帧后也检查早期失败。 |
| A P3-12，最终503摘要 | 保留设计。统一no_available_channel避免外泄上游细节；管理页保留分类原因。输入错误与本地超限现已直接给出具体原因。 |

## 管理、状态与运行边界

| 对应项 | 处理与证据 |
|---|---|
| A P3-1，手动空跑 | 已修复。检查返回真实是否执行，冲突/快照失效返回409；已完成的部分结果保留。并发监控验证第二次409、第一次200。 |
| A P3-4 / B F4，改名或文件修改清状态 | 已修复。持久化每个Key/监控连接身份指纹；名称、顺序及无关设置变更保留状态。HTTP验证改模型名无额外上游检查、故障保留；更改磁盘Webhook后重启仍保留故障。凭证/URL/上游模型/有效适配器变化才重置对应Key。旧状态首次迁移需匹配原配置摘要，否则无法可靠推断旧身份。 |
| A P3-5 / B F9，保存串行验证 | 已加边界。等待保存锁最多5秒，新/变更Key联网验证总预算60秒；失败/超时不保存，前端显示原因。保持整份配置验证通过才生效，建议批量变更分批保存。60秒不含Argon2与本地磁盘耗时；本轮未实测60秒超时。 |
| A P3-7 / B F8，登录资源与限速 | 已修复。独立1个登录许可，连续5次失败后递增退避、最高60秒。仍为进程内全局限流，重启重置，不宣称具备分布式防爆破能力。 |
| B F7，改密会话 | 已修复。密码变更清会话；登录写入会话时持有密码快照读锁，避免旧密码检查跨越改密。HTTP验证旧会话401、新密码可登录。 |
| A P3-8 / B F12，并发覆盖 | 已修复。管理状态包含_revision，保存校验并返回新版本；过期或缺版本409。HTTP验证旧快照不能覆盖新配置。 |
| A P3-9 / B F10，启动文件与持久化 | 已修复静默重置/超限panic路径。损坏或超大config/state明确报错并退出，保留原文件；拒绝自动清空故障状态的建议。Unix原子替换后同步父目录。损坏与超限启动另用临时数据验证；断电耐久性未模拟。 |
| A P3-10，监控旧检查覆盖 | 源码核对未支持该结论：同监控ID全程inflight守卫，写入前检查Arc配置快照，配置变化后旧结果丢弃。未添加重复revision机制；没有声称穷尽所有并发交错。 |
| A P3-11，恢复429耗预算 | 已修复。429延后60–3600秒（默认300），不消耗故障预算。隔离重启后自动探测429，原4次预算不变、retry_at顺延，仍保持故障。 |
| B F5，官方适配按公司模型名 | 保留明确产品规则并补文档。改按上游模型会违背原要求；管理员需按实际渠道语义命名公司模型。 |
| B F6，大配置刷新延迟 | 保留有界并发；文档明确5分钟为目标而非最大延迟承诺。慢接口和大量Key会拉长整批周期；未做512Key极限延迟验收。 |
| B F11，通知无限重试 | 已限制每通知12次失败后暂停并保留队列，变更Webhook重开预算；队列仍最多200条。正常投递/去重隔离HTTP已测，12次退避耗尽未进行长时端到端测试。 |
| A P3-6，文档与UI证据 | 已更新计数、请求值语义、超时与错误行为。指定已有Playwright模块重跑UI通过；其他审查环境缺依赖不代表既往结论虚假。 |

## 其他记录

- B P4的lone-CR分行随SSE观察器修复。
- 糖果判据仍沿用既有实现，21.5的边界未调整；并不把单题判据描述为普遍质量证明。
- 请求大小超限和全局预算拥塞现使用独立错误码/文案。
- retry_at共用、256MiB进程管理上限、无CSP仍属运维/安全加固边界；本轮没有据此扩展架构。
- 自动切换可能重复上游执行或计费，已写入ERROR-HANDLING；修复消除了上述本地大小限制、格式差异、首帧静默导致的重放，不能保证所有网络失败下恰好执行一次。
- Docker镜像、真实供应商高峰延迟、真实飞书、生产环境均未在本轮验证。

复现用例已纳入scripts/check_http.py与Rust单测，命令及验收结果见docs/ACCEPTANCE.md。
