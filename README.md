# Forest Router

公司内网使用的 Rust Responses 网关。员工配置一次公司地址和 Key，管理员按模型维护有序渠道。

- `GET /v1/models`：使用总 Key 或启用的员工 Bearer Key 鉴权，返回配置中心的对外模型列表（object=list/data）；仅包含id、object、created、owned_by，不暴露上游配置。所有已配置模型均列出，是否可用在请求时判断；created为0（未保存模型创建时间）。
- `POST /v1/responses`：模型精确匹配，替换 URL、Authorization、顶层 model；其他 JSON 值及正常响应内容透传。请求会重新序列化（键序可能变化，重复键合并），响应成功正文保持原字节。
- 渠道按优先级选择；同渠道多 Key 轮询。提供者和每把Key可独立开关，关闭提供者整组跳过，全部Key关闭也跳过该提供者；关闭的Key不参与后台额度/恢复检查，重新开启保留健康状态。质量、余额、服务状态分别显示。
- New API / Sub2API 自动识别；现有订阅站 `/v1/subscriptions`；模型名包含 deepseek / glm（忽略大小写）优先用各自官方额度接口。
- 降智监控沿用 codex-test 当前定时任务的糖果题、low、单次判据。只检测绑定到启用渠道的监控 ID。
- 浅色管理页：配置中心、Key 管理、运行统计、降智监控、日志、设置（仅配置中心显示模型侧栏）；日志只保留最近200条事件。
- 公司及上游 API Key 明文写入配置，可在页面查看编辑。管理员密码使用 Argon2。
- 无数据库，单实例运行；配置和运行状态原子写入本地文件。

## 构建与运行

需要 Rust 1.98 或更新版本。

```sh
cargo build --release --locked
export FOREST_ROUTER_HOME=/absolute/path/to/forest-data
export FOREST_LISTEN=0.0.0.0:8119
export FOREST_ADMIN_PASSWORD='首次登录密码'
export FOREST_API_KEY='公司统一Key'
./target/release/forest-router
```

启动可传 `--port 80`（也支持 `--port=80`），优先于已保存的监听地址，以 `0.0.0.0:80` 监听；不传参数沿用配置，首次初始化默认 `0.0.0.0:8119`。PM2 在 `ecosystem.config.cjs` 的 `args` 中配置，示例默认 `--port 8119`，部署按目标端口覆盖（当前另一台 Mac 使用 `--port 8117`）。设置页只读显示实际端口。启动覆盖本身不写配置；随后在管理页保存配置时会保存当前监听地址。

首次启动生成 `FOREST_ROUTER_HOME/config.json`。以后从文件读取，初始环境变量可以移除。未设置数据目录时默认使用当前目录的 `.runtime`。正式密码及飞书 Webhook 由管理员在部署时设置；仓库无固定默认密码或真实账号配置。

浏览器访问服务器的 8119 端口，创建模型、渠道和监控。添加/更换 Key 时服务端也会识别平台并验证额度接口，结果立即写入状态。未知或无法识别的平台会显示明确错误。新增/变更凭证验证总预算60秒，任一失败整份配置不保存；建议分批添加。保存需携带当前配置版本，过期编辑返回409；等待其他保存最多5秒。

客户端 Base URL 指向 `http://公司服务器:8119/v1`，使用总 Key 或员工 Key；模型填写管理页模型名。网关不修改客户端模型清单和提示词。

## 路由与恢复

质量未知/过期的受监控渠道不参与路由；未绑定监控不拦截。检测异常短暂沿用未过期的最后明确结论，异常不当作恢复。

降智监控页的“检测时间段”可统一配置全部监控的时间段与间隔，支持新增、删除、跨午夜及恢复默认。默认上海时间：09:00–23:00 每5分钟，04:00–07:00 每小时，其他每20分钟。未覆盖时间段每20分钟；起止相同表示全天，时间段不可重叠；间隔1–1440分钟，从该段起点计时。保存后重算下一次检查，既有质量结果不延长有效期。余额以每5分钟为目标刷新（慢上游或大量Key会延后），查询错误保留旧状态；新发生的请求故障不会被更早开始的查询覆盖。

正式隔离后30秒安排首次服务恢复探测（包括502、503、524）；失败后依次等待2、3、4、5分钟，之后每5分钟，实际启动可能受调度和检查并发影响延后。每个故障周期最多12次自动探测，耗尽后等待手动验证；自动恢复要求两次成功且相隔至少1分钟。不再使用冷却阻塞路由。页面只保留“重新验证”，服务验证成功立即恢复服务资格；质量和额度仍独立检查。

收到额度不足、限流、凭证错误或5xx时，响应提交前自动选择后续候选。200 SSE 开头的失败事件也会触发切换。已经转发内容后不拼接新回答；断流/失败标记供后续请求避开。全部候选不可用返回503。首帧10秒仅是观察窗口，到时开始透传并继续等待；正常EOF未识别终态只记警告，不隔离Key。输入400/413/422默认直接返回；非SSE正文不设置大小上限。

`previous_response_id` 和 `conversation` 引用上游私有会话状态，无法保证跨站移植，当前返回明确400；客户端需提交完整历史。网关不删除这些字段后伪装兼容。WebSocket、Chat→Responses转换不在本项目范围。

## 额度语义

- New API Token 查询不总能返回账号钱包。无限 Token 的负额度不判耗尽，页面标记账号余额未知。真实请求报账号没钱后，不会仅凭“无限Token”重新启用；下一轮还需最小模型请求成功。
- Sub2API 同时返回钱包与 Key 限额时取有效较小值。
- 智谱分别显示5小时/周剩余百分比和重置时间；官方 `percentage` 是已用比例。
- 订阅已知到期时间到点自动停止选择；字段缺失显示未知，不伪造余额。

## 飞书

设置页填 Webhook。质量正常→降智、额度可用→耗尽、服务正常→中断产生通知；持续异常不重复。恢复后下一次异常重新通知。同监控ID共用一个质量事件。

待发送通知和状态持久化，发送失败后台退避重试，12次失败后暂停并保留在队列；修正/更换Webhook会重开待发通知预算。Webhook没有事务性幂等确认：极端情况下“飞书已收、服务在保存确认前崩溃”可能重发；正常重启不会重发已确认消息。队列最多200条，超限记事件。

## 内存边界

业务请求不设置并发数量、请求/响应大小或总请求内存配额。上传总时限、上游连接/候选切换预算、非流式响应读取时限均为600秒；SSE每次等待下一段数据最多600秒。SSE开头10秒为观察窗口，到时进入透传，不是失败超时。后台检查、观察器、日志及通知仍保持有界。PM2不再配置内存自动重启阈值。

`state.json` 包含冷却、通知和余额缓存，删除即丢失这些状态。配置改变按每个Key/监控的实际连接身份保留或清理缓存；模型改名、其他设置修改不再清空全部故障。手改配置后需重启。损坏或超大状态文件会明确报错并停止启动，保留原文件供恢复，避免自动清空后重新放行故障Key。监听地址修改需重启。不要同时运行多个进程写同一数据目录。

管理员登录使用独立并发许可；连续5次失败后递增退避，最长60秒；修改密码撤销已有会话。该进程内限流重启后重置。官方额度适配按公司模型名选择，因此模型命名需对应实际渠道类型。

两份独立审查的逐项处理见 `docs/review/RESOLUTION.md`。错误分类、有限兜底和证据见 `docs/ERROR-HANDLING.md`；独立审查prompt见 `docs/review/REVIEW-PROMPT.md`。每个请求按配置遍历不同候选，总切换预算600秒。非SSE成功正文校验后原字节返回，不设置大小上限。

设置中的「飞书推送全量降智监控」默认关闭。开启并配置 Webhook 后，每轮定时或手动检测结束都会推送彩色汇总卡片，包含监控名称、本轮结果、响应耗时及上海时间；未参与本轮的项目明确标注，不沿用旧结果。每20项分页，复用持久化通知队列及有限重试。开启时不再另发同轮降智变化提醒，额度和服务告警不变。

## 运行统计与失败追查

「运行统计」显示上海时间今日的实际 Responses 请求数、正在处理的请求（包含流输出）、成功率、平均首字耗时和候选切换次数。仅统计公司 Key 鉴权通过的业务请求，不统计后台探测。成功率为成功 /（成功+失败）；客户端取消及正常EOF但未识别终态单独计数，不伪装成功。SSE首字为观察到文本delta的时间，非流式为完整响应校验就绪时间；无文本delta不纳入平均。候选切换包含同提供者换Key。

提供者统计按尝试计数，保留最近60个自然分钟（按完成时间归桶）。今日结果按请求开始日归属，跨日完成不会混入新一天。请求统计和最近200条失败/取消/未确认摘要随状态每10秒落盘，正常退出保存，异常退出可能损失最近一次落盘后的数据；当前并发重启归零。

Responses响应头返回网关生成的 `X-Request-ID`。在运行统计页可按ID筛选，查看候选尝试的提供者、Key ID（非凭证）、HTTP状态、固定错误分类及耗时。已开始输出表示网关向HTTP栈交付正文，不证明客户端收到；不会存储输入、答案、请求头、Key值或上游错误原文。成功请求不保留逐条追踪。

## 故障确认与优先级选择

业务连接失败、断流或未知协议错误先标记「网络异常确认中，继续可用」，后续请求仍按优先级选择该Key。约5秒后后台进行最小 Responses 验证，失败后间隔15秒再验证；从异常开始至少60秒且至少3次验证失败才正式隔离。一次验证成功即解除确认；后续异常重新获得完整确认期。同一异常期间的并发业务失败不累计验证次数、不延长窗口。调度并发和单次验证耗时（最多45秒）可能使确认超过60秒。HTTP 504按上游繁忙处理：业务请求仍记录失败并可尝试下一候选，但不改变Key状态、不触发确认或隔离；探测收到504属于无结论，不计失败也不计成功，已有确认/恢复任务延后60秒。明确HTTP 5xx（504除外）立即隔离，429按等待时间暂避，额度耗尽和凭证失效立即跳过；探测中的明确故障同样立即处理。疑似阶段不发送服务中断告警。采用最小 Responses 验证实际生成链路，models列表成功不能证明生成服务正常。

每个新请求严格按配置顺位选择可用提供者，同提供者可用Key等量轮询。不保留备用渠道，不设置恢复回切等待；高优先级恢复后下一次请求立即优先使用。已判定降智的监控关联渠道全部排除，每次候选发送前重查质量；全部候选不合格返回503，不降级使用降智渠道。已开始输出不拼接、不重放。

不增加同候选业务重试，不重放已输出的响应，候选去重，总切换预算600秒。统计区分同提供者换Key、请求内跨提供者、全局首选变动与回到高优先级次数。减少切换不保证缓存命中，不估算节省费用。

客户端请求正文上传总时限为10分钟（600秒），从开始读取正文计时；超过该时限返回408。上传完成后才开始上游候选切换预算。

手动验证成功会立即解锁该 Key；历史 cooldown_until 字段仅保留兼容，不再阻塞路由或在页面显示冷却。自动恢复也不因旧冷却时间阻塞。

手动及自动验证恢复后均按顺位参与选择，无额外回切等待。旧状态文件的 sticky_routes 字段自动忽略。

## 员工 Key 与五日用量

「Key 管理」保留不可删除的总 Key，支持新增员工 Key、查看/复制、开关及删除。员工 Key 与总 Key 均可访问模型目录和 Responses，沿用相同路由规则，不增加请求额度或并发限制。停用/删除立即拒绝新请求，已开始的请求继续完成；删除后的历史记录保留至五日窗口外。

用量按上海时间的请求开始日期归属，保留今天及前四个自然日，00:00 开始新一天；输入、缓存命中、输出分别展示，总 Token 为输入＋输出，缓存已包含在输入中；今日汇总和每日明细展示缓存率（缓存命中÷输入，保留一位小数，无输入时显示“—”），按已收到的usage计算。每个上游尝试只计一份最新有效 usage，候选切换后各次用量合计。流式大帧通过有界扫描提取 usage，不修改透传字节；未返回 usage 的请求标注缺失，已返回部分仍计入，不能视为完整供应商账单。后台检查不计入员工用量。请求模型名包含 `glm` 或 `deepseek`（忽略大小写）时，默认不累计输入、缓存及输出 Token，也不计为 usage 缺失；仍保留请求次数、最近使用时间和运行监控，无需配置。此规则仅影响更新后的请求，已有按日汇总的历史用量保持不变。

统计随运行状态每10秒原子保存，正常退出保存；异常终止可能丢失最近一次保存后的数据。失败追踪关联员工名称及 Key ID，不记录完整凭证或正文。旧配置自动兼容，员工 Key 默认空列表。

## Mac / PM2 部署

2026-09-23 部署记录：另一台 Mac 使用 PM2 托管 `forest-router`，监听 `0.0.0.0:8117`。原开发机服务和数据保留。远端已验证本机 HTTP 200，外部访问及端口映射未验证；执行了 `pm2 save`，不据此宣称已经验证整机重启自动恢复。

部署目录位于目标用户的 `$HOME/Applications/forest-router`：`repo/` 为代码，`bin/forest-router` 为运行二进制，`data/` 为完整配置与状态。首次迁移同时复制 config.json、state.json；以后更新代码不要覆盖正在使用的数据。运行二进制与源码目录分离，单独 git pull 不会更新运行程序。

远程 SSH 命令需使用 `zsh -lic` 加载用户 PATH，才能找到现有 Node/PM2。进入该 Mac 的 zsh 终端后：

```sh
pm2 status forest-router
pm2 restart forest-router
pm2 save
curl -I http://127.0.0.1:8117/
```

首次启动使用目标机器上的绝对数据目录，不能直接使用仓库 ecosystem 示例中的 `./data`：

```sh
FOREST_ROUTER_HOME="$HOME/Applications/forest-router/data"   pm2 start "$HOME/Applications/forest-router/bin/forest-router"   --name forest-router --interpreter none --kill-timeout 15000 -- --port 8117
pm2 save
```

更新时在有 Rust 的环境构建匹配目标架构/macOS版本的 release 二进制，替换 `bin/forest-router` 后再重启。首次部署使用本机构建的 Apple Silicon 二进制；后续在目标机安装最小 Rust 工具链并从源码构建。未修改其他 PM2 应用。不要同时用独立 launchd 服务与 PM2 启动同一数据目录。

目标机已安装 Rust 后，在 zsh 中更新并编译启动：

```sh
cd "$HOME/Applications/forest-router/repo"
git pull --ff-only
"$HOME/.cargo/bin/cargo" build --release --locked
cp target/release/forest-router ../bin/forest-router.next
mv ../bin/forest-router.next ../bin/forest-router
pm2 restart forest-router
pm2 save
curl -I http://127.0.0.1:8117/
```

上述更新保留 `../data`，构建失败时不要执行后续替换与重启。

## 系统代理

设置页“走系统代理”默认关闭，关闭时上游请求明确直连，不读取进程代理环境变量。开启后业务Responses、平台识别、额度查询、服务探测和降智检测使用系统代理客户端；飞书通知保持直连。macOS读取网关运行机器的HTTP/HTTPS系统代理，进程HTTP_PROXY/HTTPS_PROXY/ALL_PROXY及NO_PROXY环境变量也会影响代理选择且优先于系统配置。未配置代理的协议或命中NO_PROXY的地址仍直连；不执行PAC脚本，不读取macOS仅SOCKS的系统设置（环境变量SOCKS代理可用）。

保存后新请求立即切换，已有请求继续使用原连接。修改系统代理后重新保存设置以刷新客户端；PM2环境变量变更需更新进程环境。此开关不修改操作系统代理，也不等同于强制所有流量通过代理。
